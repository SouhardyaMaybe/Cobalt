Cobalt Wrapper v0.3.0

The renderer now dumps the shader when the driver rejects it. No setting to
turn on, no file to pull -- the dump appears in the launcher's own log, next to
the error it explains.

Why this exists

v0.2.1 put the same dump behind a "Log shader source (diagnostics)" toggle,
which is off by default. Three runs produced byte-identical failures and no
shader source, because the person reporting the failure is not the person who
knows the switch exists. A diagnostic that needs configuring before it works is
a diagnostic that does not work.

The dump now fires only when a compile fails, so the success path costs nothing,
and it goes to logcat as well as the log file.

What it will show

  ERROR: 0:224: '_uniform' : undeclared identifier
  ERROR: 0:224: '_instance_00_00' : Syntax error:  syntax error

Neither identifier exists in any of Minecraft's 106 shipped shader files. Both
are generated by Mojang's own RenderPearl recompiler, from the format strings
"_uniform_%02d_%02d" and "_uniform_instance_%02d_%02d" in
com/mojang/renderpearl/backend/opengl/GlPipelineRecompiler.

26.3 is the only version with RenderPearl, which compiles GLSL to SPIR-V with
shaderc, flattens uniforms into synthesised globals, and decompiles back to GLSL
with SPIRV-Cross before Minecraft hands it to the renderer. So what arrives at
glShaderSource is Mojang-generated text, not the files in the jar.

That also explains the version boundary: 1.17 through 26.x all launch. Only 26.3
takes this path.

Three hypotheses were formed and disproved by testing before that was found:
a substring match on "uniform" inside "_uniform" in process_uniform_declarations,
uniform block handling, and #line removal. The dump exists so the next attempt
starts from evidence.

How it works

glCompileShader is replaced. Upstream declared it as a passthrough that calls
the driver and returns, so nothing in this layer ever learns a compile failed --
by the time glGetShaderiv(GL_COMPILE_STATUS) reports it, the source is gone. The
replacement checks GL_COMPILE_STATUS and, on failure, logs the driver's info log,
the source as Minecraft supplied it, and the source after Cobalt's translation.

The original is captured at glShaderSource rather than read back at failure,
because shaderInfo is a single global holding only the most recent conversion
and Minecraft compiles vertex and fragment shaders back to back. A small ring of
four keeps them apart.

Unchanged: all 256 GL names Minecraft resolves, all three ABIs, 6.1 MB per ABI.
